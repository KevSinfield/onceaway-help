# Why Onceaway asks before it acts

There is a rule the product is built around:

**No observed event, AI output or recommendation can directly cause an action.**

In plain English: nothing Onceaway *sees*, and nothing an AI *says*, is allowed
to make something happen to your files. Only you can do that, and only by
approving the specific action in front of you.

## Why this rule exists

Think about what the alternative would mean. Onceaway watches your work, so it
would be watching for a trigger. It asks a language model for ideas, so a model
would be choosing what to do. Neither of those things can be reviewed before it
happens, and both would be operating on real files.

The moment observation can trigger action, "it noticed something" and "it did
something" become the same event — and you find out afterwards. That is the
kind of software people quite rightly do not leave running.

## What it looks like in practice

- A Pattern being noticed changes nothing.
- Confirming a Pattern changes nothing.
- Saying you want help changes nothing.
- An AI suggestion changes nothing.
- A notification changes nothing.
- **You** choosing a file, choosing a destination, reading a preview and
  pressing **Perform Move** changes exactly one thing, and you saw it described
  before it happened.

Every step before the last is information. Only the last one acts.

## The cost, and why it is worth paying

It makes Onceaway less impressive in a demo. Nothing happens by itself, and
there is no moment where it magically tidies your desktop.

It also makes it something you can leave running for months without wondering
what it did while you were not looking. That is the better trade.
